# What to update and rebuild

Klear And Klarity has **one source of truth: the web app in `frontend/`.**
Everything else (Android, iOS, Windows, macOS, Linux, PWA) is a wrapper around
the same React build. So the golden rule is:

> Change the site once → rebuild the web → re-sync the wrappers → rebuild the apps you ship.

This file tells you, for any change you make, exactly what to rebuild.

---

## 1. Set these ONCE before your first real release

| # | Thing | File to edit | Then |
| --- | --- | --- | --- |
| 1 | Real backend URL | `frontend\.env.production` → `VITE_API_URL=...` | Rebuild **everything** (section 3) |
| 2 | App name / id | `capacitor.config.json` (`appName`, `appId`) | Rebuild Android + iOS |
| 3 | Version number | `frontend\android\app\build.gradle` (`versionCode`, `versionName`) | Rebuild Android |
| 4 | Version number (desktop/iOS) | `frontend\package.json` and `desktop\package.json` (`version`) | Rebuild desktop + iOS |
| 5 | Logo / icon | replace `All Needed\Logo.jpeg`, regenerate assets (section 6) | Rebuild **everything** |

Until #1 is done, the apps point at the placeholder Zeabur URL.

---

## 2. "I changed ___ → rebuild ___" cheat sheet

| You changed | Rebuild web? | Android | iOS | Windows/macOS/Linux | PWA |
| --- | --- | --- | --- | --- | --- |
| Pages, text, styles, components | Yes | Yes | Yes | Yes | Yes |
| API URL (`.env.production`) | Yes | Yes | Yes | Yes | Yes |
| Logo / app icon | No* | Yes | Yes | Yes | Yes |
| App name / package id | No | Yes | Yes | Yes | Maybe |
| Version number | No | Yes | Yes | Yes | No |
| Android-only settings (Gradle, plugins) | No | Yes | No | No | No |
| `desktop\main.js` (window, protocol) | No | No | No | Yes | No |
| Store listing text / screenshots | No | No | No | No | No |

\* Icons are regenerated by a script (section 6), which writes into the native
projects directly, so no web rebuild is needed for the icon itself.

**Fast rule:** if it touches anything inside `frontend\src\`, `frontend\public\`,
`frontend\index.html` or `.env.production` → it's a **web rebuild** and every
platform must be rebuilt.

## 3. The universal rebuild sequence

Run the web build and sync once, then build each platform you need.

### Step A — rebuild the web (always first)

```powershell
cd "D:\HTI PROJECT @ Copy\frontend"
npm run build
npx cap sync
```

`npm run build` refreshes the website + PWA (`frontend\dist\`).
`npx cap sync` copies that build into the Android and iOS projects.

### Step B — Android (Play Store)

```powershell
cd "D:\HTI PROJECT @ Copy\frontend\android"
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat bundleRelease assembleRelease
```

New files:
- `frontend\android\app\build\outputs\bundle\release\app-release.aab`  ← upload to Play
- `frontend\android\app\build\outputs\apk\release\app-release.apk`  ← testing

### Step C — Windows / macOS / Linux (Electron desktop)

```powershell
cd "D:\HTI PROJECT @ Copy\desktop"
npx electron-builder --win      # builds on this PC
```

Output in `desktop\release\`:
- `Klear And Klarity Setup <version>.exe`  ← installer
- `Klear And Klarity <version>.exe`  ← portable

For **macOS** and **Linux**, run the GitHub Actions workflow (section 5) — those
can't be built reliably on Windows.

### Step D — iOS (App Store)

Apple requires a Mac. Use the cloud workflow in section 5; there is nothing to
run locally.

### Step E — PWA (all OS, no store)

Nothing extra. `frontend\dist\` is the app. Deploy it to your static host
(Cloudflare Pages) and it is installable on Android, iPhone, Windows and Mac.

---

## 4. If you don't want to rebuild everything

Some shortcuts:

- **Only the website/PWA changed?** Run Step A. You're done — `frontend\dist\`
  is live-ready.
- **Only text on an existing native app changed but you don't need a new store
  version?** You still must rebuild the platform, because native apps bundle
  the web files. There is no remote update unless you add a live-update tool
  (e.g. Capacitor Live Updates).
- **Only the desktop app changed?** `cd desktop && npx electron-builder --win`.

## 5. Cloud builds for iOS, macOS and Linux

These run on GitHub's machines, so no Mac/Linux needed locally.

1. Push the repo to GitHub.
2. Repo → **Actions** tab.
3. Choose a workflow and click **Run workflow**, pasting your real API URL:
   - **Build iOS app (App Store)** → `.github\workflows\build-ios.yml`
     → produces `.ipa` for App Store Connect.
   - **Build desktop apps (Windows / macOS / Linux)** →
     `.github\workflows\build-desktop.yml`
     → produces `.dmg` (macOS), `.AppImage`/`.deb` (Linux), `.exe` (Windows).
4. Download the artifacts when the run finishes.

For **signed** iOS builds, add these repo secrets first:
`IOS_DIST_CERT_P12`, `IOS_DIST_CERT_PASSWORD`, `IOS_PROVISIONING_PROFILE`,
`IOS_KEYCHAIN_PASSWORD`, and set your team id in
`frontend\ios\App\ExportOptions.plist`.

## 6. Regenerating icons / splash (when the logo changes)

```powershell
# 1. Replace D:\HTI PROJECT @ Copy\All Needed\Logo.jpeg with the new logo
# 2. Regenerate the source images and all platform variants:
& "D:\HTI PROJECT @ Copy\scripts\make-app-assets.ps1"
cd "D:\HTI PROJECT @ Copy\frontend"
npx capacitor-assets generate --android --ios
```

Then rebuild Android (Step B), iOS (CI) and desktop (Step C).

---

## 7. Version bumping checklist

Before submitting an **update** to a store, bump the version:

1. `frontend\android\app\build.gradle` — increase `versionCode` by 1, set
   `versionName` (Android requires a higher `versionCode` every upload).
2. `frontend\package.json` — `version`.
3. `desktop\package.json` — `version` (names the `.exe`/`.dmg`).
4. Rebuild the platform(s) you're shipping.

## 8. Full release checklist (copy/paste order)

```
[ ] 1. Set real backend URL in frontend\.env.production
[ ] 2. cd frontend ; npm run build ; npx cap sync
[ ] 3. Build Android: gradlew bundleRelease assembleRelease
[ ] 4. Build Windows: cd desktop ; npx electron-builder --win
[ ] 5. Run GitHub Actions: iOS workflow + desktop (mac/linux) workflow
[ ] 6. Deploy frontend\dist to Cloudflare Pages (PWA)
[ ] 7. Upload app-release.aab to Google Play Console
[ ] 8. Upload .ipa to App Store Connect (Transporter)
[ ] 9. Upload .exe to Microsoft Store (or share directly)
[ ] 10. Update store listings (what's new, screenshots)
```

Artifact locations and store-account details are in **`BUILD.md`**.
